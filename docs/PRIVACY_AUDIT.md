# Аудит HYDRA — 6 октября 2026

Аудит выполнен до реализации legal/privacy-модуля. Ниже зафиксирована исходная система; изменения и итоговая проверка приведены в COMPLIANCE.md. Это техническая инвентаризация, не заключение о законности деятельности.

## Что найдено

- Express + PostgreSQL/Prisma; Vue/React и внешних frontend SDK нет. Шрифты Manrope поставляются локально.
- Аккаунт: email, username, bcrypt hash (cost 12), роль, блокировка, информационный баланс, UUID и даты. Пароли поступают по HTTP в локальной разработке, не сохраняются открыто.
- Сессии: cookie с именем из COOKIE_NAME (по умолчанию sid), opaque token; в БД SHA-256 hash, userId, expiresAt, createdAt. HttpOnly, SameSite=Lax, Secure только в production, технический TTL из SESSION_TTL_DAYS (7 дней по умолчанию). Выход удаляет сессию; смена/сброс пароля отзывает все сессии.
- Сброс пароля: одноразовый token в письме и URL, hash в БД, срок действия 30 минут. Без SMTP development сохраняет письмо с email и ссылкой в server/storage/mail-outbox. Это персональные данные и секрет восстановления, а не обезличенный лог.
- IP обрабатывается в оперативной памяти express-rate-limit (общий лимит 1 минута, auth 15 минут). Приложение не записывает IP, User-Agent или отпечаток устройства в БД. Заголовки доступны сетевой инфраструктуре; её логи требуют отдельного аудита.
- Заказы/платежи/подписки: UUID пользователя/товара/тарифа, цены, скидки, промокод, валюта RUB, сроки доступа, статусы, платежные идентификаторы и idempotencyKey. Карточных полей нет.
- Оплата: только локальный SandboxProvider, production намеренно заблокирован. Webhook HMAC по raw bytes, timestamp, проверка payment/order/amount/currency/status, идемпотентная транзакционная активация доступа. Реального эквайринга, возврата через провайдера, чеков и автосписаний нет.
- sessionStorage checkout:<userId>:<product/plan/promo> хранит UUID повторного заказа до удаления после успеха/закрытия вкладки.
- AdminLog содержит adminId, action, entity/entityId, JSON с перечнем изменённых полей и техническими результатами, даты. Доступ server-side requireAuth + requireAdmin.
- Ошибки: stdout event/path/code/name; тексты SMTP и пароли не логируются. Исходный req.path может включать UUID; будет заменён шаблоном маршрута.
- Нет поддержки через форму, массовой email-рассылки, аналитики, рекламных SDK, cookie-баннера, записей согласий, юридических страниц, privacy-запросов и автоматической очистки development-писем.
- Product.image — настраиваемый URL. Исходный frontend немедленно загружает внешние изображения: внешний хост получает IP, технические HTTP-заголовки, потенциальный Referer; собственные cookies внешнего хоста зависят от него и браузера. Их имена/сроки в коде HYDRA не определены. Это реальная третья сторона даже без аналитики.
- Docker Compose — локальный dev PostgreSQL, порт привязан к loopback. Страна production-БД, backend, backup, SMTP, CDN и будущего эквайринга неизвестна. Нельзя вывести страну хранения из языка интерфейса или localhost.
- .env.example содержал персональный email и слабый seed-пароль. Пример будет заменён нейтральным адресом и пустым паролем; действующий .env не изменяется.

## Карта передач

USER → WEBSITE (локальные JS/CSS/шрифты) → BACKEND → DATABASE.

- USER → WEBSITE/BACKEND: аккаунт, cookie, заказы, сетевые заголовки; страна backend неизвестна; договор/выбранное согласие и безопасность.
- BACKEND → DATABASE: данные реестра выше; страна неизвестна, требуется проверка локализации RU/KZ, доступа и договоров обработки для всех стран.
- BACKEND → PAYMENT PROVIDER: исходно отсутствует внешняя передача (sandbox); будущие orderId/amount/currency и минимум контактных данных зависят от адаптера, страны и договора провайдера.
- BACKEND → EMAIL PROVIDER: только при настроенном SMTP — email, сервисное письмо, reset-link; страна и договор НЕ НАСТРОЕНО. Иначе private dev outbox на backend.
- WEBSITE → ANALYTICS: отсутствует; нельзя добавлять SDK вне consent gate.
- USER → EXTERNAL IMAGE HOST: исходно есть; IP/headers и потенциальные cookies хоста; после изменений только после отдельного выбора.
- DATABASE/OUTBOX → BACKUPS: исходно автоматизации нет; страна, ключи, доступ, сроки и исключения после удаления требуют настройки.

## Проблемы для исправления

1. Нет прозрачных документов, версии и подтверждения принятия условий.
2. Нет раздельного отзыва optional-согласий и доказательной записи.
3. Нет юрисдикции в юридическом flow; нельзя обосновать KZ модель копированием RU.
4. Нет запросов на доступ/исправление/удаление и доказательной обработки admin.
5. Неизвестны обязательные сроки и реальное размещение; не задавать фиктивные сроки.
6. Внешние изображения загружаются до информированного выбора.
7. Dev outbox хранится без очистки, возможна утечка секретов из backup.
8. Нет процедуры резервирования/восстановления и проверки возвращённых из backup удалённых записей.
9. Production HTTPS/TLS инфраструктура отсутствует, sandbox нельзя выдавать за интеграцию эквайринга.

Актуальная консолидированная редакция и разъяснения РКН не подтверждены полностью: NEEDS LEGAL REVIEW, не заявлять завершённую проверку.
- KZ: прочитан [официальный Закон №94-V](https://old.adilet.zan.kz/rus/docs/Z1300000094), [правила №395/НҚ](https://old.adilet.zan.kz/rus/docs/V2000021498). Модель требует подтверждаемого отдельного согласия/проверенного исключения; хранение и трансграничная передача проверяются отдельно (ст. 7–8, 12, 16). В источнике есть изменения 2026 года; дату вступления и применимость каждого изменения проверяет специалист.

Текст закона недоступен через web-инструмент (403); источник cookie-разъяснения — [официальный канал Центра](https://t.me/s/cpd_by/440), технические и иные cookies различаются. Текущую редакцию, исключение для договора, права/сроки и трансграничную передачу обязательно перепроверить.
- Потребительские правила нельзя свести к «цифровые товары не возвращаются»: квалификацию продукта, права и сроки проверяют отдельно по каждой стране. [Официальный закон KZ](https://old.adilet.zan.kz/rus/docs/Z100000274_). RU/BY актуальные потребительские нормы требуют отдельной проверки.
